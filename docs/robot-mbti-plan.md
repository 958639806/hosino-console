# 被叫人机就破防 / 盲猜 MBTI：只读方案
2026-10-20 21:45（UTC+8）。只改了暂存区，没部署，也没新增任何 mem0 调用。
注意编号：研究文档 fun-round6-research.md 里，“被叫人机破防”是 §2，“盲猜 MBTI”是 §5（不是 1 和 6）。以下按内容处理。

## 1 被叫人机就破防（robotBit）
- 机制：有人说了 `robotBit.keywords` 里的词（不用 @，因为 gate 本来就把所有群消息交给模型），她回一句“你才人机！你全家都是人机！……好吧我是，但我是最有人味的那个。”的变体。
- **认真问优先**：命中 `sincereKeywords`，或者是私聊里语气认真地问，**一律如实说自己是 AI**，不演、不否认。这条写死在技能和 gate 里，没有开关可以关掉。这次会话段剩下的时间里也不再破防。
- 每段一次：
  - 纯技能做不到可靠计数，所以**放进 HOSINO-FUN-CONTEXT gate 补丁**。gate 在 `before_dispatch` 里，按群记“上次有消息的时间”和“这一段是否已经破防过”。沉默超过 `segmentGapMin`（30 分钟）就算新的一段。
  - 命中触发词，并且本段还没破防、没超过每群每天上限、不在技术模式，就在 appendContext 注入“可以破防一次（玩梗），之后笑过去”。已经破防过的段落里注入“本段已破防，别再演，淡定承认就好”。
  - 状态只放内存，重启后清零，可以接受。
- 技能 `humanlike-voice` 里加台词风格和变体（避免每次一字不差），并写清护栏。

## 2 盲猜 MBTI（mbti）——纯技能
- 只在有人请求时触发（“星野猜我 MBTI/星座”）。被请求时模型本来就会回复，不需要 gate 提示。
- 素材只有两样：本会话里这个人公开发在群里的消息，加上本轮 autoRecall **已经注入**的记忆。**不新增 mem0 调用，不写入，不订阅事件**。私聊内容不能用在群里。
- 回答格式：先给结论，再举 1–2 条无害的证据（作息、用词、表情包习惯），语气是玩笑、自夸“大师”，不贬低人，也不下定论。
- 禁止推断 `forbiddenTopics`（健康、性取向、宗教、政治、家庭、收入……）。素材少于 `minPublicMsgs` 就说“素材不够”。
- 上限（每人每天 1 次、每群每天 5 次）：由技能调用 `fun_mbti.py check <group> <openid>`，读写 `fun/mbti-usage.json` 执行，不需要改 gate。
  - 如果不想加脚本，也可以退一步：交给 gate 的同一个补丁计数（被请求的轮次检测关键词）。推荐用脚本，不占 gate 的复杂度。
- 退出名单里的人请求了，也礼貌拒绝。

## 参数（已加进暂存的 humanlike schema，默认全关）
新增 `robotBit.*` 和 `mbti.*`，字段表见 `staging/fun/API-v2.12-fun.md` 的“被叫人机就破防、盲猜 MBTI”一节。校验：keywords 和 sincereKeywords 不能有相同项，列表去重忽略空白和大小写。`perGroup` 和 `optOut` 也支持这两个功能名。测试全部通过，连跑 5 次都稳定。

## 合并上线
- robotBit 的段落计数并入 **HOSINO-FUN-CONTEXT**，跟着那一次网关重启。mbti 是技能加脚本，不需要重启。控制台 schema 跟着 v2.12 的那一次控制台重启。

## 风险和测试
- 风险：
  - 把认真的提问当成玩笑：认真问的信号优先，拿不准时按认真处理。
  - MBTI 被当成真心评价、伤到人：措辞护栏写在技能里，加上禁区话题，并且只在被请求时才做。
- 测试：
  - 单元测试：模拟段落切分、每段一次、认真问时不注入破防、每天上限、mbti 脚本的上限。
  - 一次性会话（deliver:false）检查台词和措辞。
  - 上线后由凛在群里实测。
