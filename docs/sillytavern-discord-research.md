## A 类：在控制台里观察和调教星野

### A1 世界书式按需设定（拟人化）
- **来源**：SillyTavern World Info 文档 https://docs.sillytavern.app/usage/core-concepts/worldinfo/ （AGPL，只借思路）。
- **热度**：ST 本体 34.7k star，2026-10-03 仍在推送。
- **原理**：每个条目由关键词、内容和触发规则组成。触发规则包括：
  - 概率：命中关键词后按概率注入。
  - 粘滞（sticky）：触发后连续 N 轮保持生效。
  - 冷却：触发后 N 轮内不再触发。
  - 延迟：聊天满 N 条后才允许触发。
  - 分组：同组条目一次只取一条。
  - 递归：条目内容里出现的关键词可以继续触发别的条目。
  - 扫描深度：只看最近几条消息。
- **和已有点子的区别**：AstrBot 报告里的“设定集”是检索式的，查到就注入。这里借的是**触发规则**：粘滞让话题持续几轮，冷却防止她反复提同一件事，分组让同一个设定有几种讲法、每次随机换一种。后两点正好对付“复读机”。
- **搬到星野的思路**：
  - 控制台加一个“设定条目”页，条目存成 JSON。
  - 先做一个技能 `lore`：SKILL.md 告诉星野“遇到人名、地名、群梗时先查”，脚本按关键词、概率、冷却和粘滞返回命中的条目，状态存在本地文件里。
  - 第二步再考虑并进黑话词典和称呼表共用的 gate 注入，到那时就不靠模型自觉，每轮都会自动带上。
- **价值**：高　**工作量**：中
- **只用技能**：部分（技能版靠模型主动查）　**重载**：技能版免重载；gate 版需重载，可以和黑话词典一起做
- **额度**：每次命中多 50–300 token

### A2 Author's Note 式风格纠偏（拟人化）
- **来源**：ST Author's Note 文档 https://docs.sillytavern.app/usage/core-concepts/authors-note/
- **热度**：同 ST 本体　**许可证**：AGPL，只借思路
- **原理**：一段很短的提示，固定插在离最新消息 N 条的位置，可以设成每 N 轮插一次。这样风格提醒总离模型的注意力很近，不会像系统提示那样被长上下文冲淡。
- **搬到星野的思路**：
  - 控制台加一个“风格便签”，可以按群设置。例如“最近太爱用颜文字，少用”“别每句都反问”。
  - 可以设注入频率和到期时间，比如 3 天后自动失效。
  - 这是临时纠偏用的，和 A1“按群人设”（长期规则）不同。
- **价值**：高（调教最直接的手段）　**工作量**：小
- **只用技能**：否（技能不保证每轮都读）　**重载**：需重载一次，以后改内容免重载（gate 读数据文件）
- **额度**：每轮多 20–80 token

### A3 下一轮一次性引导（拟人化 / 调教）
- **来源**：Guided-Generations（GPL-3.0，只借思路）　**热度**：92 star，最后推送 2025-03-26
- **原理**：用户给 AI 的“下一次回复”附一句指导，只生效一次，用完就扔。
- **搬到星野的思路**：
  - 控制台在某个会话上点“给下一句加提示”，例如“下次有人问作业就装傻”。
  - gate 在这个会话的下一次回复里注入这句，然后自动清掉。
  - 控制台记录这条提示用在了哪一句，方便看效果。
- **价值**：中高　**工作量**：小
- **只用技能**：否　**重载**：和 A2 一起做，只重载一次
- **额度**：几乎无

### A4 状态和变量框架，带变更审计（拟人化，基础设施）
- **来源**：
  - MVU https://github.com/MagicalAstrogy/MagVarUpdate （MIT，112 star）
  - 酒馆助手的变量接口
  - ST 的 `/setvar` 变量（属于 STscript）
- **原理**：
  - 模型在回复末尾输出 `_.set('路径', 值)` 这样的更新命令。
  - 脚本解析这些命令，按 schema 校验，再用代码钳制范围，比如单次变化不超过 ±3。
  - 只把当前状态注入给模型，不靠模型记住历史，所以很省注意力。
- **和已有点子的区别**：AstrBot 拟人化报告第 8 条只提了 mood 一个值。这里借的是**通用框架**：
  - 星野自己的状态：精力、在做什么、穿什么、最近在迷什么。
  - 群级状态：群里正在进行的梗、未完结的话题。
  - 每次变更都留日志，控制台可以看曲线、回滚到某个值、手动改值。
- **搬到星野的思路**：
  - 技能 `state`：脚本提供 get 和 set，会校验 schema、钳制范围、写日志。
  - SKILL.md 规定“状态有变化时调用 set”。
  - 读取先靠技能；要每轮自动带上当前状态，就得在 gate 里注入。
- **价值**：高　**工作量**：中
- **只用技能**：部分　**重载**：技能版免重载；自动注入需重载一次
- **额度**：每轮多约 50–150 token，调用工具时还有少量额外开销

### A5 阶段目标和自动检查（拟人化）
- **来源**：Extension-Objective（AGPL，40 star，最后推送 2025-06-07）
- **原理**：给角色设一个目标，由模型拆成几个子任务。每 N 条消息问一次模型“完成了没有”，完成了就切到下一个子任务，并把当前子任务注入提示。
- **搬到星野的思路**：凛在控制台给星野设一个本周的小心愿，例如“想让群友推荐一部冷门番”“想学会一句方言”。
  - 技能 `objective` 存目标和进度。
  - 星野在合适的时候自然提起，群友帮她完成后，由她调用脚本打勾。
  - 控制台能看到进度和完成在哪一句。
  - 这会让她显得有自己想做的事，而不是只会被动接话。
- **价值**：中高　**工作量**：小到中
- **只用技能**：能（检查完成由模型调用脚本，不用另外轮询）　**重载**：免重载
- **额度**：少量

### A6 手动划段做“记忆书”（调教）
- **来源**：SillyTavern-MemoryBooks（AGPL，318 star，最后推送 2026-10-17，很活跃）
- **原理**：用户在聊天里标出起止两条消息，把这一段总结成一条结构化记忆，写进世界书，并可以设关键词触发。
- **和已有点子的区别**：mem0 是自动抽取的。这里是**凛自己挑一段**有意义的群聊，比如一次大事件、一个梗的诞生，一键生成一条“剧情记忆”。审核后再写入 mem0，或者写进 A1 的设定条目。
- **搬到星野的思路**：在控制台聊天页多选消息，点“生成记忆”，调用一次 LLM 写出摘要，凛编辑后保存。
- **价值**：中高　**工作量**：中
- **只用技能**：控制台功能，不需要技能　**重载**：免重载（控制台写 mem0 要凛另行批准）
- **额度**：每次一次 LLM 调用

### A7 人设打包成角色卡 v3，做版本管理（实用）
- **来源**：角色卡 v2 规范（199 star，2023-06-22）、v3 规范（MIT，114 star，2024-07-20）
- **原理**：v3 规范把人设、示例对话、开场白、自带世界书（character_book）、作者备注、扩展字段打包成一个 JSON 或 PNG。v3 还支持资源和装饰器语法。
- **搬到星野的思路**：
  - 控制台一键把 AGENTS.md、SOUL.md、IDENTITY.md、设定条目、状态 schema 导出成 v3 卡，用来备份、比较版本、回滚。
  - 也可以导入社区角色卡，但只拿来参考，不直接套用。
  - 这是纯控制台功能。
- **价值**：中　**工作量**：小到中
- **只用技能**：不需要技能　**重载**：免重载
- **额度**：无

### A8 世界书条目自动推荐（调教）
- **来源**：WorldInfo-Recommender（MIT，133 star，最后推送 2026-06-09），可以参考代码
- **原理**：让 LLM 读最近的聊天，建议新增或修改哪些世界书条目，用户逐条采纳。
- **搬到星野的思路**：
  - 给 A1 配一个“建议条目”按钮，手动触发或每天随群报跑一次。
  - 从最近的聊天里提出新人名、新地点、新设定，进待审区。
  - 和黑话词典的待审区共用同一个审核界面。
- **价值**：中　**工作量**：小（在 A1 的基础上加）
- **只用技能**：控制台功能　**重载**：免重载
- **额度**：每次一次调用

## B 类：星野在群里的新玩法（拟人化和实用技能）

### B1 多日剧情事件弧（拟人化）
- **来源**：
  - ST 世界书的粘滞、延迟、分组触发
  - 中文酒馆“事件卡”的常见写法（未核实具体仓库）
- **原理**：预先写好事件，事件有开始、经过、结束，按时间或聊天条数推进。例如“星野感冒了”：第 1 天嗓子哑，语音变少；第 2 天好转；第 3 天痊愈。
- **和已有点子的区别**：AstrBot 拟人化报告里的生活日程是每天生成一段，不连贯。这里是**跨天连续、有状态的剧情**，和 A4 的状态框架联动，群友问起时她能接上前情。
- **搬到星野的思路**：
  - 技能 `events`：事件库是 JSON，脚本按日期推进并返回“今天的进展”。
  - 凛可以在控制台排期、手动触发或叫停。
  - 主动在群里宣布事件要走主动消息，受配额限制【平台】，建议只在群友找她时提起。
- **价值**：高　**工作量**：中
- **只用技能**：部分（要每轮自动带上，得靠 A4 的注入）　**重载**：技能版免重载
- **额度**：少量

### B2 群友说“重来”就换个说法（拟人化 / 实用）
- **来源**：ST 的重新生成（swipe），Discord 角色机器人常见的 reroll 按钮（例如 Tzurot、Viel-ai，未逐一核实）
- **原理**：保留同一轮的多个候选回复，用户可以左右翻，也可以让它重新生成。
- **搬到星野的思路**：
  - 群友回复星野的消息说“重来”或“换个说法”，她换一种风格重答。
  - 控制台记下被要求重来的原句，这是现成的差评样本，可以送进“拒答和翻车记录”。
  - 用贴表情给两个版本投票【平台】，官方 API 大概率不支持，所以不做。
- **价值**：中高（还顺带补上了“没有点踩数据”的缺口）　**工作量**：小到中
- **只用技能**：能（SKILL.md 规定：被要求重来时，先调脚本记录，再换风格重答）　**重载**：免重载
- **额度**：每次一次正常回复

### B3 群投票和接龙报名（实用）
- **来源**：Discord 常见的投票和活动机器人（例如 Sesh、Apollo，闭源，只借功能）。开源仓库未核实。
- **原理**：发起投票或报名，记录每个人的选择，到截止时间出结果。
- **搬到星野的思路**：
  - 群友说“星野发起投票：周末吃啥 A/B/C”。技能脚本建投票，群友回复“投 B”，星野调用脚本计票，被问起时汇报结果。
  - 报名接龙同理，比如“周六开黑 +1”。
  - 截止时主动公布结果受主动消息配额限制【平台】，所以改成有人问时再报。
- **价值**：高（群友真的会用）　**工作量**：小
- **只用技能**：能　**重载**：免重载
- **额度**：少量，只有调用工具的开销

### B4 拼单和 AA 记账（实用）
- **来源**：Discord 记账机器人（例如 Splitwise 类机器人，开源仓库未核实）
- **原理**：记录“谁付了多少、谁该分摊”，最后算出最少几笔转账就能结清。
- **搬到星野的思路**：
  - 群友说“星野记账：我付了奶茶 60，我、A、B 三人分”。脚本记账，计算交给代码，不让模型算数。
  - 有人问“谁欠谁”时，星野用自己的口吻报出来。
  - 控制台能查看和修正账目。
- **价值**：中高　**工作量**：小
- **只用技能**：能　**重载**：免重载
- **额度**：少量

### B5 一句话换算和速查（实用）
- **来源**：Discord 通用工具机器人的常见功能（未核实具体仓库）
- **原理**：汇率、时区（群友在不同时区时很有用）、单位换算、日期差，都用确定性的脚本计算，避免模型算错。
- **搬到星野的思路**：
  - 技能 `calc`。汇率走免费 API，要先确认条款；时区和日期在本地算。
  - 回答时由星野用自己的口吻包装一下，比如“东京现在凌晨 3 点哦，他应该睡了”。
- **价值**：中　**工作量**：小
- **只用技能**：能　**重载**：免重载
- **额度**：少量

### B6 星野的“小号”角色串场（拟人化，低优先）
- **来源**：PluralKit（AGPL，331 star，2026-10-19 仍活跃）、Tupperbox（开源仓库未核实）、Tzurot、WaifCord（多角色加轮流发言机制）、ST 群聊模式（按名字提及、自然顺序或随机选谁发言）
- **原理**：Discord 用 webhook 换名字和头像，让一个机器人扮演多个角色。ST 的群聊模式按“被提到名字的优先，其次按活跃度或随机”决定谁发言。
- **搬到星野的思路**：QQ 官方 Bot 不能换名字和头像【平台】，只能用前缀区分，比如“【星野的猫】喵”。偶尔让一个固定配角吐槽一句，规则参考 ST 的选谁发言策略。
- **价值**：低到中（容易显得做作）　**工作量**：中
- **只用技能**：能（技能里写配角设定和出场规则）　**重载**：免重载
- **额度**：少量

看过但不推荐：
- **Expressions 情绪立绘**：和 GalGame 对话框重复。
- **Quick Replies 和 STscript**：本质是给用户的快捷按钮和脚本语言。QQ 里没有对应的界面，控制台给真实群发东西又是红线。
