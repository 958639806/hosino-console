# 星野表情包改进方案（只读评估）

2026-10-20 16:50（UTC+8）。这次全程只读：服务器上没改任何东西，也没调网关的写方法。AstrBot meme_manager 是 AGPL 许可，只借鉴思路，不抄代码。

## 0. 结论

1. 现在已经有一套表情包系统，但还不成熟。改进应该在现有的四块上做，不要另起一个新技能：
   - `qq-group-sticker` 技能
   - `sticker_manager.py`
   - qqbot 里的 `&&分类&&` 标签补丁
   - 插件 qq-group-followup-gate 的群聊提示
2. 参数**不放 openclaw.json**。把 `manifest.json` 和 `params.json` 两个文件直接放在 `workspace/stickers/` 目录里。两套识别分类的代码只认图片后缀，这两个 json 不会被当成表情包。
3. 读这两个文件的两段插件代码要先改一次。改完需要一次插件重载，QQ 会短暂断一下。之后控制台再改这两个文件，5 秒内生效，不用再重载，也不用碰 openclaw.json。
4. 概率、冷却、静默时段、按会话开关这些规则，必须由代码执行。如果只写在技能说明里，靠模型自己判断，执行不稳定。

## 1. 现状

### 1.1 文件在哪
- **库目录**：`~/.openclaw/workspace/stickers/`，16 张图，每个分类只有一张。原图 1.9–2.8 MB，边长 1024 以上。
- **发送用的缩略图缓存**：`~/.openclaw/media/qq-sticker-cache/`，16 张，最长边 512，每张约 0.5 MB。
  - 由 qqbot 补丁在后台用 ffmpeg 生成。
  - 文件名格式 `<原名>.<大小>.<mtime>.512.png`。原图改名或替换后会自动生成新的缓存，旧缓存留着没用但无害。
- **技能**：`~/.openclaw/agents/main/agent/workshop-skills/qq-group-sticker/SKILL.md`，目录里只有这一个文件，没有清单，也没有参数。要点：
  - 只在有人**明确要表情包**时才用。日常顺手配图走 `&&分类&&` 标签。
  - 流程：先运行 `sticker_manager.py get "<情绪>"`，再用 message 把图当文件附件发出去（asDocument），不配文字，也不加隐形字符。
  - 还写了发送被钩子拦截时怎么排查。
- **脚本**：`workspace/scripts/sticker_manager.py`（v2，493 行），配套 `scripts/sticker_models.json`（生图模型链）。说明文档：`docs/STICKER_PLAYBOOK.md`。
- **规则**：
  - `AGENTS.md` 第 73–74 行：发表情用 `message media=stickers/xxx.png`；取图用 `sticker_manager.py get`。
  - 第 110 行左右：群聊在回复最后单独一行写 `&&分类&&`，最多 1 个。日常不要跑 exec 和 get，因为 get 遇到库里没有的分类会现场生图，要 1–2 分钟。
- **索引和映射**：**没有单独的索引文件**。分类完全由文件名推出来。各处的出处：
  - 同义词表写死在 qqbot 的 `dist/index.cjs` 里（`__QQMT_SYN`），共 14 个分类。“潜水”和“骑鲨鱼”没有同义词。
  - 每个群的计数状态在 `~/.openclaw/qqbot/media-tag-state.json`。
  - 参数在 `openclaw.json` 的 `channels.qqbot.mediaTags`。

### 1.2 命名规则（两套代码解析方式不一样）
- `sticker_manager.py`：
  - 自动生成的文件命名 `<情绪>-<模型id>.png`，手动入库的命名 `<情绪>-手动入库.<后缀>`。
  - `parse_name` 先去掉已知的来源后缀（模型 id 或“手动入库”），去不掉就按**最后一个** `-` 切开。
  - `find(key)` 依次按完全相同、`key-` 前缀、包含 key 三种方式匹配，再按画风排序（gpt-image-1.5 和 gpt-image-2 优先）。
- qqbot 标签补丁和 followup-gate：分类取文件名中**第一个** `-` 前面的部分，跳过以 `.` 开头的文件，只认 png/jpg/jpeg/gif/webp。目录读取结果缓存 30 秒（gate 插件缓存 5 秒）。
- 两套规则冲突的情况：
  - 文件名里分类之后还有别的 `-` 时，两边会切出不同的分类。
  - `add` 用的是 `shutil.copy2`，**同一个分类第二次手动入库会直接覆盖**前一张。

### 1.3 “自动入库”怎么触发
- 唯一的自动入库是 `sticker_manager.py get`：库里没有这个分类，就沿模型链（gpt-image-2 → 1.5 → doubao → grok）生成一张，存成 `<key>-<model>.png`。
  - 触发者：她自己跑脚本，或者有人明确要新表情。
  - 去重：只看同名文件是否已存在，不做内容哈希。会花额度。
- `add <key> <path>`：手动入库，不去重，会覆盖同名文件。
- 收到别人发的表情（`media/qqbot/downloads/…`）**不会**入库。

### 1.4 现在有哪几条发送途径
1. **`&&分类&&` 标签**（群聊日常的主要途径）：
   - followup-gate 每轮往提示里加一句“表情包：回复最后单独一行写 &&分类&&（只能用：开心/喜欢/…）”。“潜水”这一类不出现在菜单里。
   - 刚发过时提示改成“刚发过表情包，这轮不发”；连续很久没发会加一句建议。
   - 模型写了标签后，由 qqbot 的 QQ-MEDIA-TAG-PATCH 解析：
     - 标签不规范也能认：全角、拼音、英文、同义词。
     - 先发文字，再单独发一张 512 缩略图。
     - 冷却（`stickerCooldownReplies=3`）、8 条回复内不重复同一张（`avoidRepeatWithinReplies=8`）、每条最多一张，都是**代码强制**执行的。
     - 静默的轮次不发。
   - **只在群聊生效**：代码拿不到群 id 就直接返回，所以私聊不支持标签。
   - **没有概率、没有静默时段、不能按群开关**，只有总开关 `enabled` / `stickers`。
2. **技能和脚本**（明确要表情时）：`sticker_manager.py get` 加 `message` 发送附件，没有冷却。
3. **潜水表情 lurkSticker**（插件 keepalive.js）：
   - 群里安静至少 25 分钟、保活跑过之后，按概率 0.1 掷骰子。
   - 00:00–08:00 不发，每天最多 3 张，不连发，只在 379363 那个群生效。
   - 不经过模型，固定发“潜水”那张，而且它也不在标签菜单里。
   - 跟标签途径**各自计数，互不影响**。
4. 三条途径怎么配合：标签途径和潜水途径共用库目录和 512 缓存，但计数各管各的。技能途径完全不受冷却限制。

### 1.5 哪里不成熟（有证据）
- **图太少**：每类只有 1 张。avoidRepeat 想换一张同类的，也没得换。
- **发得太少**：
  - 两个群的标签计数：b4ee… 群共 696 条回复，最近一张表情包是 10-17 15:38（卖萌）；379363 群共 966 条回复，最近一张是 10-11 19:56（骑鲨鱼）。
  - 近两天日志里没有一条 `[qq-media-tag]` 记录。
  - 38 个会话的历史里，`stickers/` 路径只出现 5 次，几乎全是“开心”。
  - 可能的原因：只靠模型自己决定写不写标签，菜单里也只有分类名、没有使用场景说明，于是模型很少主动用。
- **场景容易不对**：菜单只列了分类名。像“骑鲨鱼”这种没有含义说明的分类，模型不知道什么时候该用。同义词表写死在插件代码里，库里新加分类后不会跟着更新。
- **命名乱**：两套解析规则不一样；文件名里带着模型名（gpt-image-2 / 1.5 / 手动入库），这对选图没有任何帮助；add 会覆盖已有文件。
- **文档和实际不一致**：PLAYBOOK 写的是冷却 2、约 6 条后提示，实际配置是冷却 3、12 条后提示。
- **私聊完全不支持标签。**

## 2. 怎样按场景选图：评估探路猫的方案

探路猫的想法是：技能、清单、参数文件三样，控制台只改后两个文件，不碰 openclaw.json。方向是对的，但要做三处调整。

- **不新建技能**：改进现有的 `qq-group-sticker` 技能。把 SKILL.md 改成“三条途径怎么分工”和“清单在哪”的说明。
- **清单 `stickers/manifest.json`**：
  - 每个分类写 `{desc: 一句话含义, scenes: [适用场景], avoid: [不适用场景], synonyms: [...]}`。
  - 每个文件写 `{file, category, sha256, addedAt, source, enabled}`。
  - followup-gate 生成菜单时，从清单里取每个分类一句不超过 12 字的场景说明，例如“骑鲨鱼=得意出场/炫耀”。
  - qqbot 补丁从清单里读同义词，跟代码里写死的那份合并。
- **参数 `stickers/params.json`**：

  | 参数 | 含义 |
  | --- | --- |
  | `attachProbability` | 0–1，这一轮是否在提示里给出表情菜单 |
  | `cooldownReplies` | 冷却回复数，用来覆盖 mediaTags 里的值 |
  | `quietHours: {start, end, tz}` | 静默时段 |
  | `sessions: {<groupId或c2c openid>: {enabled, probability?}}` | 按会话开关和单独的概率 |
  | `defaultEnabled` | 没单独设置的会话默认开不开 |

- **由代码执行，不靠模型**：
  - followup-gate 的 `mediaHint` 是唯一决定“这轮给不给菜单”的地方。会话没开、在静默时段内、或者概率没掷中时，这一轮就不放菜单。
  - 同时 qqbot 补丁在实际发送前再检查一次会话开关和静默时段。这样就算模型自己写了标签，也会被丢掉，并记到日志。
  - 冷却继续用 qqbot 现有的代码；参数文件里有值时以参数文件为准。
  - 不建议把概率和冷却写进 SKILL.md 让模型自己遵守，执行不可靠。
  - `sticker_manager.py` 只负责“明确要表情”这条途径，不需要加概率；可以加一个按会话的开关检查。
- **私聊**：要支持的话，qqbot 补丁要能处理 c2c 会话（现在拿不到群 id 就直接返回），gate 插件的提示也要覆盖私聊。工作量中等。建议放到第二步做。

### 控制台能不能写这些文件
- 现在不能。控制台的 systemd 设置是 `ProtectSystem=strict`、`ReadOnlyPaths=/`，可写目录只有 logs、backups、data 三个。
- 需要加一行 `ReadWritePaths=/home/ubuntu/.openclaw/workspace/stickers`，**只开这一个目录**，manifest、params、图片都在里面。
- 目录权限是 ubuntu 755，控制台本身以 ubuntu 身份运行，权限够用。
- 这是在 ~/.openclaw 下面写文件，**违反现有硬规则，需要凛单独批准**。
- 两个 json 放在这个目录里不会被当成表情包：两套解析代码都只认图片后缀。备份放到以 `.` 开头的子目录，例如 `stickers/.trash/`：gate 和 qqbot 跳过点开头的文件名，sticker_manager 只看顶层文件。

## 3. 对上下文和回复质量的影响，以及参数何时生效
- **提示长度**：菜单现在大约 60 字；每个分类加一句说明后，16 类大约 250–300 字（约 150–200 token）。这部分只在群聊里出现，而且本来就是每轮动态生成的，不会影响系统提示的缓存命中。分类多于 30 个时，建议只列启用的分类，或者按场景只列前 N 个。
- **技能加载**：SKILL.md 只在需要时读取，清单不放进 SKILL.md，所以不增加上下文。
- **生效时间**：
  - gate 插件读 `media-tag-state.json` 时缓存 5 秒，目录列表缓存 5 秒；qqbot 补丁的目录缓存 30 秒。
  - 新代码读 manifest 和 params 时，也做成按文件修改时间刷新，5–30 秒内生效，**不用重载**。
  - 反过来，如果参数放在 openclaw.json 里：`plugins.*` 和 `channels.*` 一改就会触发重载全部插件，QQ 会断一下。这就是把参数放在文件里的好处。

## 4. 导入和改名流程（控制台）
- **格式**：png、jpg、webp、gif（动图保留原样）。用文件头的字节判断真实格式，不信后缀。
- **大小**：单张不超过 5 MB（现有原图最大 2.8 MB），边长 128–4096 之间。不在控制台缩放，发送时由 qqbot 自动生成 512 缩略图。
- **去重**：算 sha256，跟清单里已有的哈希比较（第一次上线时给现有 16 张补算），重复就拒绝，并告诉用户和哪张重复。
- **自动命名**：`<分类>-手动入库<序号>.<后缀>`，例如 `开心-手动入库2.png`。
  - 分类必须在清单里有，或者新建（新建要求 1–8 个中文、字母或数字，不能有 `-`，不能以 `.` 开头）。
  - qqbot 和 gate 按第一个 `-` 切，得到的分类是“开心”，没问题。
  - `sticker_manager.find("开心")` 用前缀匹配能找到，没问题。
  - `parse_name` 要改一处：它现在会把“手动入库2”当作来源后缀，这本身没问题，但要让 `list` 输出也能显示序号。
  - `add` 也要改成“已经存在就加序号”，不再覆盖。
  - **复用现有的命名规则，不另起一套。**
- **改名**：只能改分类或序号，来源后缀保持不变。
  - 先把原图复制到 `stickers/.trash/<时间>-<原名>`，然后原子重命名，同时更新清单。
  - 新名字已存在就拒绝。最多保留 30 天或 100 份备份。
  - qqbot 的缓存按文件大小和修改时间区分，改名后会自动重新生成缩略图。
  - `media-tag-state.json` 里 lastStickerFile 还是旧路径，只影响“不重复同一张”的判断，无害。
- **删除**：只是移进 `.trash`，不真删。
- 每次写入都记到 ops.log，接口需要 X-HS 和 confirm，跟现有的写接口一样。

## 5. 推荐步骤
1. **第一步（不碰任何东西）**：控制台继续只读展示，并修正表情排行。已经做完。
2. **第二步（需要批准）**：
   - 控制台的 systemd 设置加上 stickers 目录可写，重启控制台。
   - 实现导入、改名、清单、参数这几个接口。
   - 第一次上线时生成 manifest（16 张，补算哈希、补写场景说明的草稿给凛审）。
3. **第三步（需要批准，QQ 会断一下）**：
   - 改 followup-gate 的 `mediaHint`：读 params 和 manifest，加上概率、静默时段、会话开关、场景说明。
   - 改 qqbot 标签补丁：发送前再检查一次，同义词从清单读。
   - 更新 SKILL.md、PLAYBOOK、AGENTS.md 第 110 行。
   - 重载插件一次。
4. **第四步（可选）**：支持私聊标签；每个分类补到 2–3 张图。

## 6. 风险
- 改 qqbot 的 dist 属于继续打补丁。qqbot 插件一升级，补丁就会被覆盖，要做成可以重复执行的补丁脚本，并加版本标记。
- 控制台能写 stickers 目录后，等于控制台可以影响 QQ 实际发出去的图。需要内容格式校验、备份和审计日志。
- 发送概率调太高会刷屏。建议默认 0.3，并保留代码层的冷却作为兜底。
- 场景说明是给模型看的提示，能提高选对场景的概率，但不能保证每次都对。

## 7. 需要批准的事项
- 控制台 systemd 设置加 `ReadWritePaths=/home/ubuntu/.openclaw/workspace/stickers`。这是在 ~/.openclaw 下写文件，触碰硬规则。
- 修改 `plugins/qq-group-followup-gate/index.js`、qqbot `dist/index.cjs`，以及 workspace 里的 SKILL.md、AGENTS.md、PLAYBOOK，然后**重载插件一次**（QQ 会短暂断开）。
- **不需要改 openclaw.json**。mediaTags 里的 stickerDir 默认就是 workspace/stickers；新参数全部放在 params.json。
